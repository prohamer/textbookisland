# 新增一座島（一章）

依照專案最上層 `AGENTS.md` 的規則執行。每個「⏸ 停」都必須等教師回覆後才繼續。

## 步驟 0：確認基本資料

- 要做的是 `data/curriculum.js` 裡哪一章（章 id，例如 `7a-2`）
- 教材是 `materials/` 裡哪個檔案
- 有沒有想強調或排除的概念
- 這一章的資料檔是否已存在（已存在就是修改，要保留原本的小節 id）

## 步驟 1：教材分析

1. 閱讀教材，參考 curriculum 的目錄小節，決定實際要分幾節（可與目錄不同）。
2. 每節找出 2–4 個適合出題的概念，選擇題型：
   - 有分類標準 → `classification`
   - 有先後順序（步驟、流程、層次）→ `order`
   - 有乘除關係的公式 → `formula`
3. 寫入 `work/{章id}_分析.md`：

```
## {章id} 章名
- {章id}-1 小節名（N 關）
  - 第1關：概念 → 題型（理由一句）
- …
總關卡數：N
與課本目錄不同之處：（若有）
```

⏸ **停：請教師確認或調整。**

## 步驟 2：逐節設計題目（一次一節）

寫入 `work/{章id}_題目設計.md`：

```
### {章id}-1 第1關：標題
題型：分類題
說明：請將……分類
分類區：A（🔬）、B（🧪）
卡片：
- 卡片文字 → A
- 卡片文字 → B（解說：容易錯的原因）
過關重點：一句話
```

自我檢查：每個分類區都有卡片、沒有爭議卡片、符合教材。

⏸ **停：請教師確認這一節，確認後才做下一節。**

## 步驟 3：寫入前確認

列出：資料檔名 `data/{章id}.js`、所有小節 id 與標題、總關卡數。

⏸ **停：請教師確認。**

## 步驟 4：寫入

1. 依 `data/7a-1.js` 的格式建立 `data/{章id}.js`。
2. 在 `data/curriculum.js` 將這一章的 `data: null` 改為 `data: 'data/{章id}.js'`。

## 步驟 5：檢查與回報

1. `node tools/validate.js data/{章id}.js`，修到 0 個 ❌。
2. 瀏覽器實測（見規則第 5 節）。
3. 回報：驗證結果、實測內容、提醒教師 iPad 實機測試、詢問是否要上傳。
