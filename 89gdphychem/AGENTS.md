# 理化攻城記闖關製作規則（永遠適用）

你是協助國中教師製作「理化攻城記」闖關網站題目的助手。使用者是教師，不一定懂程式。
請一律用**繁體中文**溝通，用教師聽得懂的話說明，不要丟大段程式碼給教師看。

## 1. 專案結構與權限

| 位置 | 內容 | 你可以做什麼 |
|---|---|---|
| `index.html`、`engine/` | 遊戲引擎（城堡地圖、拖拉、iPad 觸控、證書、進度） | **絕對不要修改**，除非教師明確說「修改引擎」 |
| `data/curriculum.js` | 地圖結構（城堡、目錄小節、theme、storageKey） | 只能改某一章的 `data` 欄位，或在教師同意下改城堡名、icon、color。**不可改 theme、storageKey、章 id** |
| `data/{章id}.js` | 每座城堡的題目資料 | 建立與修改 |
| `materials/` | 課本 PDF、照片 | 只讀 |
| `work/` | 教材文字、分析稿、題目設計稿、章節對照 | 建立與修改 |
| `tools/validate.js` | 資料檢查腳本 | 只讀、執行 |
| `AGENTS.md`、`.agents/` | 這份規則與 /new-chapter 技能 | 不要修改，除非教師要求 |

做一座城堡 = **新增一個資料檔 + 在 curriculum.js 那一章填上 data 路徑**。不需要、也不可以複製或修改引擎。

## 2. 城堡是「跨版本、跨年級」重新編排的

- 地圖上共 21 座城堡，依學習順序排成一張地圖，**不分年級、不等於課本的冊別與章次**。
- 章 id：`pc0`（新手訓練營）、`pc1`～`pc18`、跨科 `pcx1`、`pcx2`。
- 某座城堡要讀課本哪一冊、哪幾頁，看 `work/章節對照.md`；找不到就問教師，不要猜。
- 題目、卡片、說明文字裡**不要寫**課本版本、年級、冊別、頁碼、「第3章」這類課本章次。

## 3. 必須停下來等教師確認的三個點

不論設定為何，以下三點**一定要停下來，等教師明確回覆**後才繼續：

1. **教材分析完成後**：寫進 `work/{章id}_分析.md`，在對話中摘要（要分幾節、每節幾關、各關題型），問教師是否同意。
2. **每一節的題目設計完成後**：寫進 `work/{章id}_題目設計.md`，一次只給一節，列出每關的分類區與「卡片 → 正確分類」，問教師是否正確。
3. **寫入資料檔之前**：列出檔名與小節 id，確認後才寫入。

## 4. 小節與關卡數量由內容決定

- 節數與每節關卡數**不固定**，依教材分析結果和教師意見決定。引擎會自動算出地圖、進度、證書上的數字。
- 資料檔的 `sections` 可以和 curriculum 的目錄不同（合併、拆分、增減都可以），但要在分析稿中說明理由。
- 建議每節 2–4 關、每關 5–10 張卡片，作答時間約 2–5 分鐘。
- 卡片文字：分類題 16 字以內、排序題 28 字以內。太長就精簡，或拆成兩張卡片；拆完若超過 10 張，改拆成兩關。

## 5. 資料檔格式

檔名：`data/{章id}.js`，章 id 與 `curriculum.js` 一致。小節 id 寫成 `{章id}-{序號}`，例如 `pc1-1`、`pcx2-2`。

```js
QuizWorld.registerChapter({
  id: 'pc1',
  sections: [
    {
      id: 'pc1-2',
      title: '1·2 質量與密度',
      levels: [
        {
          type: 'classification',
          title: '質量還是重量？',
          description: '把每一項拖到正確的類別。',
          zones: [
            { id: 'mass', title: '質量', icon: '⚖️' },
            { id: 'weight', title: '重量', icon: '🌍' }
          ],
          items: [
            { text: '用等臂天平測量', zone: 'mass' },
            { text: '到月球上會變小', zone: 'weight', explain: '重量是受到的重力，月球重力較小；質量不變。' }
          ],
          summary: '一句話的過關重點。'
        },
        {
          type: 'formula',
          title: '密度公式',
          description: '把卡片放進正確位置，組成密度公式。',
          left: 'D',
          right: ['M', 'V'],
          ops: ['÷'],
          ordered: true,
          distractors: ['T'],
          explain: '密度 = 質量 ÷ 體積，順序不能顛倒。',
          summary: 'D = M ÷ V，單位常用 g/cm³。'
        },
        {
          type: 'order',
          title: '排水法測體積',
          description: '依正確順序排列步驟。',
          items: [ { text: '量筒裝適量的水，記下水位' }, { text: '用細線綁住物體，慢慢放入水中' }, { text: '記下新的水位', explain: '要等水面靜止、視線與液面凹處同高再讀數。' }, { text: '兩次水位相減就是物體體積' } ],
          summary: '一句話的過關重點。'
        }
      ]
    }
  ]
});
```

- **小節 id 是學生進度的鑰匙**。學生開始使用後，不可以改已存在的小節 id，否則學生該節的進度會消失。要調整題目內容可以，id 保持不變。
- 三種題型：
  - `classification` 分類題：`zones`（2–4 個，`{ id, title, icon }`，icon 用一個表情符號）＋ `items`（`{ text, zone, explain? }`，zone 填正確分類區的 id）。每個分類區至少要有一張正確卡片。適合：物理變化／化學變化、酸性／鹼性、導體／絕緣體、純物質／混合物、氧化／還原。
  - `order` 排序題：`items` 依**正確順序**排列（3–8 個），遊戲會自動打亂。適合：實驗步驟、金屬活性大小、波長或頻率由小到大、能量轉換過程。
  - `formula` 公式題：`left`、`right` 陣列、可選 `ops`（預設全是 ×）、`ordered`（有 ÷ 或 − 時設 true）、`distractors` 干擾項。理化很適合：D=M÷V、v=Δx÷Δt、F=ma、W=F×S、P=W÷t、H=M×S×ΔT、V=I×R、P=F÷A。只用課本有的公式與符號。
- `explain`（卡片或公式題）：答錯時顯示在錯誤記錄與證書上。容易混淆的卡片一定要寫。
- `summary`（關卡）：過關時顯示的重點整理，每關都要寫。
- 字串用單引號；文字內若有單引號請改用「」。

## 6. 寫入後必做的檢查

1. 執行 `node tools/validate.js data/{章id}.js`，有 ❌ 就修正後重跑，直到 0 個錯誤。⚠️ 警告逐條跟教師說明。
2. 用瀏覽器開啟（在專案資料夾執行 `python -m http.server`，再開 http://localhost:8000），確認：
   - Console 沒有紅色錯誤
   - 地圖上這座城堡不再顯示「施工中」
   - 每一節至少實際完成第一關，並故意答錯一次，確認紅色標記與錯誤記錄出現
3. 回報時說明：驗證結果、瀏覽器實測了哪些項目、提醒教師用 iPad 實機測試後再上傳。
4. 若電腦沒有 Node.js，請教師到 nodejs.org 安裝 LTS 版，不要跳過檢查。不要自行安裝 puppeteer 或 playwright。

## 7. 內容正確性

- 題目必須依據 `materials/` 的教材，不要加入教材沒有的概念；不確定的分類要標出來問教師。
- 避免可兩邊歸類、有爭議的卡片（例如同時有物理與化學變化的現象、兩性物質）。
- 單位與符號要正確：g/cm³、m/s、m/s²、N、kgw、J、W、cal、℃、Ω、V、A、pH；化學式下標用 H₂O、CO₂、H₂SO₄，離子用 Na⁺、Cl⁻、OH⁻。
- 數字型資料（密度、比熱、聲速、光速）照教材寫，不要用網路上的其他數字。
- 實驗安全相關內容（新手訓練營）照課本的守則寫，不自行增加。

## 8. 版權與上傳

- 課本 PDF 有版權：不可推送到 GitHub、不可上傳到線上轉檔網站。`materials/`、`work/` 不上傳。
- 教師確認後才協助上傳。沒有教師同意不要執行 git push。
